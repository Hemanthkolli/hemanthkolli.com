From a Raspberry Pi to an AI agent: how I connected my home with MCP

23 Nov 2026 · 4 min read · #mcp #homeassistant #aiagents #typescript #smarthome

It started with a tip from my brother: Home Assistant, free software that brings all your smart devices into one app, whatever the brand. No more five apps for one home.

I had a spare Raspberry Pi (a tiny, cheap computer), so I tried it. That small experiment grew into something I now use every week: an AI agent that helps run my home, connected through MCP.

In short
  • Home Assistant on a Raspberry Pi puts all my devices in one free app.
  • A small MCP server I wrote lets an AI agent read and manage it.
  • It's off by default, my key stays on my computer, and every change waits for my yes.

Step 1: Home Assistant on a Raspberry Pi

I installed Home Assistant on the Pi and added my devices one by one. Soon I had dashboards, a few automations ("when this happens, do that") and lots of devices with names like light.living_room_2.

It still runs on that same Pi. But managing it meant clicking through screens, writing settings files and tidying names by hand. That last job I kept putting off.

Step 2: "What if I could just ask?"

What if I could just ask "Create a dashboard for me" and have it done?

That's what MCP makes possible. In fact, it was one of the first things I asked, and the agent built the dashboard once I approved it.

What is MCP?

The Model Context Protocol is an open standard for connecting AI agents to apps. Think of a restaurant menu: the app lists what it can do (its tools), the agent reads the menu and orders, and the kitchen does the cooking. Write the menu once, as an MCP server, and any MCP-capable agent can use it.

Step 3: A small MCP server for Home Assistant

I wrote one in TypeScript with the official MCP toolkit, about 600 lines. It talks to Home Assistant's own interfaces and gives the agent 20 tools:

AreaWhat the agent can do
Reading the homeList what every device is doing, look at a single device, read history, fill in templates (small formulas that combine readings)
Controlling devicesSend commands, for example turning lights, switches or scenes (saved groups of settings) on and off
AutomationsList, read, create, update, switch on or off, and delete automations
DashboardsList, read, create and update dashboards
Tidying upRename entities and devices, organise areas and floors
NotificationsSend a notification to my phone

The agent never touches Home Assistant directly. It only sees the tools; the server does the real work.

A real example: heating

Each room has its own smart thermostat. Checking and adjusting them used to be a chore.

Now I just ask:

  • "What's the temperature in each room?" One overview.
  • "How warm was the bedroom over the last day?" It checks the history.
  • "Set the office to 21 °C." Done.
  • "Turn the heating off when the season ends." It writes the rule, shows it, and saves it only after I approve.
  • "Build me a heating dashboard." All rooms on one screen.

I say what I want; the agent works out how. I still decide.

Security, kept simple

  • Off by default. A small script turns the server on for a few hours, then off again.
  • The key stays local. My Home Assistant access key lives in a file on my computer, never in a chat.
  • I stay in the loop. The agent asks before it changes anything.

What I learned

  • MCP was the easy part. The real work was writing clear tool names and descriptions.
  • Good error messages matter. A clear error lets the agent fix itself instead of guessing.
  • Boring jobs become easy. Renaming and sorting devices, put off for months, took one conversation.
  • Small is fine. One small server for something you use daily teaches you most of it.

Want to try it?

My code is open source (MIT licence): Hemanthkolli/home-assistant-agent-mcp. Other good starting points:

  • No code: Home Assistant's built-in MCP Server integration.
  • Python: FastMCP, or the official Python SDK.
  • TypeScript: the official TypeScript SDK, which I used.
  • Testing: the MCP Inspector.
Tip

Start read-only. Add the tools that change things once you trust how the agent behaves.

Closing thought

A tip from my brother and a spare Raspberry Pi became my favourite way to learn about AI agents. I'm still learning. If you've connected your home to an agent, I'd love to hear how.
