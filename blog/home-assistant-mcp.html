From a Raspberry Pi to an AI agent: how I connected my home with MCP

23 Nov 2026 · 6 min read · #mcp #homeassistant #aiagents #typescript #smarthome

It started with a tip from my brother: Home Assistant, a free, open-source platform that brings all your smart devices together in one place, no matter which brand they come from.

That tip solved a real problem. Smart devices from different brands usually come with their own app, and the hubs that bring them together are often paid or only work with some brands. You end up with several apps to manage one home, which makes life more difficult instead of easier. Home Assistant costs nothing and works across brands.

I was curious, had a Raspberry Pi, and gave it a try.

This is the story of how that small experiment grew into something I now use every week: an AI agent that can understand and manage my home through MCP, the Model Context Protocol.

Step 1: Home Assistant on a Raspberry Pi

The first version was simple. I installed Home Assistant on the Raspberry Pi and added my devices one by one. After a while I had dashboards, a few automations, and a lot of devices with names like light.living_room_2.

It worked well, and it still runs on that same Pi today. But managing it still meant clicking through screens, writing YAML for automations, and keeping names and rooms tidy by hand. That last part I kept postponing.

Step 2: Asking "what if I could just ask?"

At the same time, I was learning more about AI agents in my free time. The question came naturally:

What if I could just ask "Create a dashboard for me" and have it done?

One of the first things I asked the agent was exactly that, and it built a dashboard for me after I approved the change.

That is exactly the problem MCP solves.

What is MCP, in one paragraph

The Model Context Protocol is an open standard for connecting AI agents to tools and data. An application describes what it can do as a set of tools, each with a name, a description and its inputs. Any agent that speaks MCP can discover these tools and use them when they fit the goal. Instead of writing one integration per agent, you write one MCP server, and every MCP-capable agent can use it.

Step 3: Building a small MCP server for Home Assistant

I built a small MCP server in TypeScript using the official MCP SDK. It is around 600 lines of code and talks to Home Assistant through two of its interfaces:

  • the REST API for states, services and history
  • the WebSocket API for configuration, such as the device, entity and area registries

It gives the agent 20 tools, grouped roughly like this:

AreaWhat the agent can do
Reading the homeList states, look at a single device, read history, render templates
Controlling devicesCall services, for example turning lights, switches or scenes on and off
AutomationsList, read, create, update, enable/disable and delete automations
DashboardsList, read, create and update dashboards
Tidying upRename entities and devices, organise areas and floors
NotificationsSend a notification to my phone

The agent never talks to Home Assistant directly. It only sees these tools and their descriptions, and the MCP server does the actual calls.

A real example: heating

Heating is where this helps me most. My rooms have their own smart thermostats, and managing them used to mean opening each one, checking temperatures and adjusting schedules by hand.

Now I can simply ask:

  • "What's the temperature in each room right now?" The agent reads the thermostats and sensors and gives me one overview.
  • "How warm was the bedroom over the last day?" It looks at the history, so I can see if a room heats up too slowly or too much.
  • "Set the office to 21 °C." It calls the right climate service for that thermostat.
  • "Turn the heating off automatically when the heating season ends." It writes the automation for me, shows it, and only saves it after I approve.
  • "Build me a heating dashboard." All rooms, temperatures and target settings on one screen.

What I like most is that I describe what I want in plain words. The agent figures out which devices, services and automation rules that means. I still decide, because every change waits for my yes.

Security, kept simple

Giving an agent access to your home deserves some care. I kept it simple:

  • Off by default. A small script switches the MCP server on for a few hours and turns it off again automatically. When I'm not using it, the agent has no access at all.
  • The token stays local. The Home Assistant access token lives in a local file on my machine. It never goes into a chat or a prompt.
  • I stay in the loop. The agent always asks for my approval before it changes anything, so I can say yes or no.

None of this is complicated, but it makes a big difference to how comfortable I feel using it.

What I learned

The MCP part was the easy part. The SDK does most of the protocol work. The real effort went into writing clear tool names and descriptions, so the agent picks the right tool the first time.

Good error messages matter. When a tool fails, the agent reads the error. A clear message such as "this entity has its own area, so its name can't be cleared" lets it correct itself instead of guessing.

Boring jobs become easy. Renaming devices and sorting them into the right rooms, the job I had postponed for months, became a single conversation.

Small is fine. You don't need a big platform to learn MCP. One small server for something you use every day teaches you most of the concepts.

Want to try it yourself?

The code is open source, so you can use it and change it for your own home: Hemanthkolli/home-assistant-agent-mcp (MIT licence).

You also don't have to start from my code. A few other good starting points:

  • No code: Home Assistant now has a built-in MCP Server integration.
  • Python: FastMCP lets you define a tool in a few lines.
  • TypeScript: the official TypeScript SDK, which is what I used.
  • Python, official: the official Python SDK.
  • Testing: the MCP Inspector lets you try your tools before you connect an agent.

Closing thought

What started with a tip from my brother and a spare Raspberry Pi became my favourite way to learn how AI agents and integrations work together. I'm still learning, and I'm sure there are better ways to do parts of this.

If you've connected your own home or tools to an agent, I'd love to hear how you did it.
